# Plan: the crook herdr-app mod

Area 3 of 4: the mod shipped in the release's `mod/` folder. The other areas are the `crook` binary (1), the
Claude Code plugin (2), and release, CI and e2e tooling (4).

## Goal

The maintainer can start, reopen and close a flock from herdr-app. The mod is one dialog. It calls the
`crook` binary for every step and shows crook's errors. It draws no flock tree: herdr-app's own Spaces and
Agents sidebars show the flock ([0021](../architecture/decisions/0021-show-flocks-with-herdr-apps-own-tree.md)).

## Scope and non-goals

In scope:

- A "Flocks" dialog with three actions: New flock, Open, Close
  ([0003](../architecture/decisions/0003-coordinator-session-delegates-to-children.md) step 1,
  [0020](../architecture/decisions/0020-mechanical-steps-run-through-crook.md):44-46).
- Calling crook through mise's shim, or `CROOK_BIN` when set
  ([0019](../architecture/decisions/0019-ship-crook-as-a-binary.md):56-66).
- A list of flocks inside the dialog, from `crook status --json` (0020:50,
  [0024](../architecture/decisions/0024-flock-file-formats.md):36). It shows each flock's name, date and
  whether it is running. That is the only status the mod shows. Without a slug, `crook status` lists every flock
  (Q5).
- One command-palette entry. A sample key binding in the docs, not installed.
- `mod.json`, `herdr-app check`, unit tests for the mod's pure logic, and what `crook setup` must do to install
  and upgrade the mod (0019:84-89, Q22).
- Tests that validate the mod's status handling against the committed JSON Schema for `crook status --json` (Q5).

Non-goals:

- No flock tree, no children list, no panel for roster-only children. 0021:39-40 leaves that to a later
  decision. Keep it out of this version.
- No docked panel and no flock panel in the mod. `mod.json` uses `"place": "none"`, so the app docks nothing
  (`~/.config/herdr-app/AGENTS.md`:938-939). 0019 no longer names a panel (Q24).
- No repository, folder or notes-root fields in the dialog. Repositories are per child, through
  `crook spawn --repo` ([0023](../architecture/decisions/0023-crook-manages-child-worktrees.md):26-30).
  `notes_root` is a global setting ([0026](../architecture/decisions/0026-config-file.md)).
- No reopening of closed flocks, no deletion, no rename.
- No entry in herdr-app's "+" menu or space menu. Those are shipped mods (`new-menu`, `spaces`). Editing them
  needs a clone, and 0021 rejects forking herdr-app's sidebars.
- No edits to the maintainer's `keys.json`. Any edit makes the whole file the person's
  (AGENTS.md:535-537), and herdr's docs say not to pick keys on one's own (AGENTS.md:564-569).
- No `space.new`, from the mod or from crook. crook places every terminal through labels
  ([0015](../architecture/decisions/0015-spaces-from-herdr-labels.md), Q24).
- Children on other machines (`exec … { on }`): out of scope, as in
  [0022](../architecture/decisions/0022-rust-fresh-code-v1-tooling.md):32-33.

## Facts that shape the design

Each was read or run on 2026-11-27.

- `exec` starts a program directly, with no shell, and rejects when the program cannot start
  (herdr.d.ts:10-14). So `${CROOK_BIN:-…}` only works inside `sh -c`.
- `exec` times out after 30 s by default, up to 600 s (herdr.d.ts:11).
- `exec`, `hc` and `writeTextFile` really run during `herdr-app check`. Guard them with `checking()`
  (AGENTS.md:1018-1021).
- `mod.open` takes only `name` and opens "the overlay its mod.json describes" (`herdr-app commands`). So a
  palette entry or key cannot pass props. One dialog serves all three actions.
- The palette skips duplicate command and argument pairs (AGENTS.md:936). So there can be only one palette
  entry that runs `mod.open {name: "crook"}`.
- `machine-add/mod.json` declares `"overlay": { "kind": "dialog", "width": 560 }`; `picker/mod.json` also sets
  `height`.
- The shipped `confirm` mod runs an app command, not a program (`mods/confirm/main.js`:15-19). It cannot run
  `crook close`. The confirm step lives in the crook dialog.
- `terminals()` gives every core terminal with its `labels`, `parent` and `state`, and re-renders when they
  change (herdr.d.ts:253-260). hc keeps labels as a JSON object of key to value (`hc get <t> --json`, run on
  2026-11-27). That `terminals()` passes the same object through is from herdr.d.ts, not run. The shipped
  `agents` mod tests `state === "live"` (`mods/agents/main.js`:175).
- Children carry `crook.flock` too ([0007](../architecture/decisions/0007-launch-children-with-hc-run.md):42),
  and a child without a kept tab has no `herdr.space` label (0021:34-36). So a live terminal's labels can tell
  whether a flock is running, but not reliably which space it is in.
- `herdr-app check <dir>` on a scratch copy of the `prompt` mod passed and wrote `gpui-kit.d.ts` (827 KB) and
  `jsconfig.json` into the checked folder. `herdr-app check <dir> --print-spec` printed the rendered element tree
  with ids. Both run here, in the scratchpad.
- A mod cannot learn its own folder name (spike 17). `crook setup` always installs to `mods/crook/` (0019:86),
  so `mods/crook/` is a fixed path.
- Saving any file under the mod reloads every open copy. Hidden files and `jsconfig.json` do not trigger a
  reload (AGENTS.md:940-945).

## File layout

In the repository:

```text
mod/
  mod.json        place "none", the dialog overlay, the palette entry
  main.js         the View: list, new-flock form, close confirm
  lib.js          pure logic, no imports: argv, JSON parsing, slug check, error text, warning lines
  RECIPE.md       for herdr.dev; points to mise (0019:115-116); never installed
tests/mod/
  lib.test.mjs    node --test unit tests for lib.js, with status JSON checked against the committed schema
```

`mod/` holds only what ships. Tests live outside it so they never reach the release archive. The repository's
`.gitignore` gains `mod/gpui-kit.d.ts` and `mod/jsconfig.json`, which `herdr-app check` writes.

Installed by `crook setup`:

```text
<appHome>/mods/crook/
  mod.json
  main.js
  lib.js
  .crook-version  the crook version that installed it (0019:86)
```

`<appHome>` is `$HERDR_APP_HOME`, else `~/.config/herdr-app` (herdr.d.ts:21-22; spike 17; Q22).

## UI sketch

The maintainer opens the command palette and picks "Flocks". A dialog opens in the middle of the window, about
560 px wide, in the look of the shipped `worktree` dialog.

### List view (opens first)

- Title "Flocks", with "Esc" on the right.
- First row: "+ New flock…". It is selected when the dialog opens, so Enter goes straight to the form.
- Then one row per flock whose state is `active`, running flocks first, then newest first. Each row shows the
  slug, the date from the last part of `folder` (an absolute path), and a badge: "running" (accent colour) or "paused" (dim).
- The selected row shows two buttons on its right: "Open" and "Close…".
- While `crook status --json` runs, the list shows "…". When it fails, the list shows crook's message in the
  `blocked` colour and a "Retry" button. With no flocks, only the "+ New flock…" row shows.
- Footer: "↑↓ choose · ↵ open · esc close". When the installed mod's `.crook-version` differs from the binary's
  version, the footer adds "Run `crook setup` to update this dialog."

Open on a running flock selects its space and closes the dialog. Open on a paused flock runs `crook open`,
then selects the space.

### New flock form

- Title "New flock".
- "Name" field (`Input`): the slug. Hint below it: "Lower-case letters, digits and dashes. Used for the
  folder, the space and branch names." An invalid name shows the hint in the `blocked` colour and disables
  Create.
- "First task" field (`Textarea`, about 6 rows, optional): "What the coordinator should start on. Leave empty to
  start it with its standard prompt." (Q1)
- Buttons: "Back" (to the list) and "Create". Enter in the Name field creates. The textarea keeps Enter for new
  lines; the Create button always works.
- While crook runs: the fields are read-only, a spinner (`.frames`, as in `mods/worktree/main.js`:398) and
  "starting…" replace the buttons, and Esc is ignored.
- On success: the dialog closes and the flock's space is selected. On failure: crook's message shows under the
  form in the `blocked` colour, and both fields keep their text.

### Close confirm

- "Close flock `<slug>`?" and one line on what closing does. The text follows what `crook close` does (Q6):
  "Ends its coordinator and children, marks it done, and removes clean worktrees. Branches stay."
- Buttons: "Cancel" and "Close flock". Enter confirms, Esc goes back to the list.
- On success: a toast "Flock `<slug>` closed". If crook printed `warning:` lines on stderr, one for each worktree
  it kept (0023:31-32, Q6), the toast is a warning and lists them. On failure: the message shows in the dialog.

## How the mod runs crook

Every call goes through one function in `main.js`, built from `lib.crookArgv(args)`:

```js
exec("sh", ["-c", 'exec "${CROOK_BIN:-${MISE_DATA_DIR:-${XDG_DATA_HOME:-$HOME/.local/share}/mise}/shims/crook}" "$@"', "crook", ...args],
     { cwd: home(), timeout: 120_000 });
```

- This is the same expression as the plugin's hook commands (0019:61-63). It never calls a bare `crook` or a
  versioned path (0019:56-60).
- The slug and the task are positional arguments to `sh`. They never enter the script text, so no quoting or
  injection problem arises.
- The timeout is 120 s, not the default 30 s, because `crook new` and `crook open` may start the hc core and
  rename the space (0020:90-91, 0021:30-31). That value is a guess; M6 measures it.
- `if (checking()) return;` comes before every call (AGENTS.md:1018-1021).
- Error text, from `lib.errorText(result)`:
  - exit 0: no error;
  - exit 127 (sh found no program): "crook was not found at `<path>`. Install it with mise, run `crook setup`,
    or set `CROOK_BIN`.";
  - any other exit: the first non-empty line of stderr, else of stdout, else "crook exited with code N";
  - `exec` rejected (timeout, no `sh`): "Could not run crook: `<error>`".

The mod only runs crook commands. It never refreshes itself: only `crook setup` installs or updates the mod
(Q22).

Whether `CROOK_BIN` reaches `exec` at all is not known. Spike 21 checked `PATH` only. M0 checks it.

## Dependencies on the other areas

### Area 1: the `crook` binary

The mod calls exactly these. Each prints a one-line, human-readable error to stderr and exits non-zero on
failure. The mod shows the first line.

| Command | When | The mod needs |
| --- | --- | --- |
| `crook status --json` | The dialog opens; after `new`, `open`, `close` | JSON on stdout, below. With no slug it lists every flock; `crook status <slug>` gives that flock and its children (Q5) |
| `crook new <slug> [--task <text>]` | Create | Exit 0 once the coordinator terminal has started, without waiting for Claude. Refuses a slug any flock already uses, closed ones included (Q1, Q2) |
| `crook open <slug>` | Open on a paused flock | Exit 0 once started. Refuses a closed flock. With a live coordinator it only redoes the renames and starts no second one (Q7) |
| `crook close <slug>` | Close | Kills the coordinator, marks the flock done, removes clean worktrees. One `warning: …` line on stderr for each worktree it keeps (Q6) |
| `crook setup` | Install and upgrade | See below |

`crook status --json`, the fields the mod reads:

```json
{
  "version": 1,
  "crook_version": "0.1.0",
  "flocks": [
    {
      "slug": "login-bug",
      "folder": "/home/me/.local/share/crook/flocks/2026-11-27-login-bug",
      "state": "active",
      "space": "crook-login-bug"
    }
  ]
}
```

- The JSON Schema for this output is committed to the repository (Q5), and is the full contract; the example
  shows only what the mod reads. The mod's tests validate against the schema (M1.2).
- `version` is the JSON's own format number. The mod refuses a version it does not know and asks for
  `crook setup`. Extra fields are ignored, so crook can add them freely.
- `slug` is what `new`, `open` and `close` take, and the value of the `crook.flock` label.
- `space` is the `herdr.space` label value crook gives the coordinator (0015, 0020:45). The mod never builds it.
- `state` is the coordinator's roster state, `active` or `done` (0024:49).

Other needs:

- Every terminal of a flock carries `crook.flock=<slug>` (0007:42, 0020:45). The mod treats a flock as running only
  when its coordinator terminal (no `crook.child` label) is live and shows an agent (`program.agent`, D52). It takes
  the space only from the status JSON's `space`.
- crook publishes the slug rule, and the mod copies it into `lib.checkSlug`. Names are at most 16 characters
  (build-log D27), because the slug goes into a folder name, a space id, an hc label and a git branch
  (`crook/<flock>/<child>`, 0023:26). The rule is `^[a-z0-9]+(-[a-z0-9]+)*$`, at most 16 characters, and not
  starting with `t` and a digit (D27, D36; they replace Q12 and Q45).
- `crook new` and `crook open` rename the space and the tab (0021:30-33) after the terminal starts. The app may
  not know the space yet when crook asks; crook retries the rename for a few seconds rather than fail.
- `crook setup`:
  - finds appHome as `$HERDR_APP_HOME`, else `~/.config/herdr-app` (Q22);
  - installs the files of `mod/` except `RECIPE.md`, `preview.png`, `jsconfig.json`, `gpui-kit.d.ts` and dot
    files (AGENTS.md:492-495);
  - builds the new folder in a staging folder outside `mods/`, because a new folder under `mods/` is a new mod
    to the app, then swaps it for `mods/crook/`. The marker goes in last. Writing files one by one into
    `mods/crook/` would reload an open dialog on a mix of old and new files (AGENTS.md:940-945);
  - stops when `mods/crook/` exists without `.crook-version` (0019:87-88), and refuses to replace a mod whose
    marker is newer than the binary's version;
  - is the only command that installs or refreshes the mod;
  - prints the command to trust each root, so CI can skip that step (Q22).
- `crook doctor` checks the mod's marker against its own version (0019:100). Unchanged from the ADR.

## Risks

- **`CROOK_BIN` may never reach the mod.** Finder and Dock launches load the login shell's `PATH`
  (AGENTS.md:824-825); other variables are untested. Then a dev build cannot be driven from the app without
  `launchctl setenv` or a restart from a shell. M0.1 answers it.
- **Esc or a click beside the dialog while crook runs.** If the app closes the dialog anyway, the running `exec`
  keeps going (AGENTS.md:1086-1087). The mod's own task that waits for the result is probably cancelled with
  the copy: inferred from AGENTS.md:1083-1084 (unfinished tasks are cancelled after `close()`) and herdr.d.ts:520
  (closing a copy cancels its pending calls); not run. The flock would still start, but an error would go
  unseen. M0.1 checks `modal` and Esc.
- **crook calls back into the app while the mod waits.** `crook new` runs `herdr-app do space.rename` while the
  mod's `exec` is pending. Not tested; M6.1 shows it.
- **The space shows up late.** `space.select` on an id the app does not know yet fails. M3.2 waits for
  `spaces()` to list it.
- **The mod and the binary drift.** mise upgrades the binary; the mod changes only at the next `crook setup`.
  The status JSON's `version` and the footer hint cover this, and the command arguments must stay backward
  compatible between versions.
- **A non-standard mise data folder.** The shim expression follows `MISE_DATA_DIR` and `XDG_DATA_HOME` as mise
  does (0019), so only a mise configured some other way needs `CROOK_BIN`.
- **`herdr-app check` never runs in CI.** CI cannot run herdr-app (Q34). A change that passes `node --check` and
  the shape checks can still fail `herdr-app check`; pre-commit and the e2e run catch it.
