# Build log

The unattended build, milestone by milestone. Each milestone is implemented, reviewed adversarially, fixed,
checked and pushed. Decisions made without the maintainer are recorded here with the reason, so they can be
reviewed and reversed.

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| D1 | Build order: release M0 (tooling base), binary M0, release M1 (CI), then the binary milestones in order, then the plugin, the mod and the remaining release milestones. | The release plan's "Order against the other plans" puts M0 and M1 before the binary's first checked milestone, and the plugin and mod depend on binary subcommands. |
| D2 | Each milestone: a Sonnet agent implements it, an Opus agent reviews it adversarially, a Sonnet agent fixes the confirmed findings, then local checks run before the commit. | Sonnet is the cheapest model that implements well; adversarial review is the hard-reasoning step, so it gets Opus. |
| D3 | Work lands on `main` and is pushed after each milestone, with no pull requests. | The maintainer set main-only work for this session. |
| D4 | `mise.toml` pins rust 1.99.1 (minimal profile with clippy and rustfmt), cargo-nextest, cargo-edit, cargo-llvm-cov and git-cliff; no node and no `mise.ci.toml` yet. | Release M0.1 lists these; node and the CI lock belong to later milestones. |
| D5 | Restored tools tests define `REPO_ROOT` locally instead of importing it from a `tools/ci.py` that does not exist yet. | `tools/ci.py` arrives with release M4; creating it early would be dead code. |
| D6 | Tests for `tools/ci.py`, `tools/release.py`, workflow safety and e2e scripts are left out until their subjects exist. | A test for missing code fails or tests nothing. |
| D7 | Crate dependencies are added by the task that first uses them; milestone 0 has only `clap` and `thiserror`. | No unused dependencies to audit or update. |
| D8 | `crook hook <event>` and `spawn <role>` take free strings, not enums. | A clap usage error exits 2, but a hook must always exit 0 (0020); roles are plugin agent files, not a fixed list. |
| D9 | `crook --help` lists no `help` subcommand. | Task 0.1 says the help lists exactly the 0020 commands plus `setup` and `doctor`. |
| D10 | The runner returns a non-zero exit as normal output with its code, not as an error; after exit it drains pipes until both close or 300 ms pass with no data. | `hc send` exit codes carry meaning (spike 2); a descendant holding a pipe open must not hang a finished command. |
| D11 | A timeout kills the child's whole process group (`process_group(0)` and `killpg`), adding `nix` with only the `signal` feature. | The review showed grandchildren outliving a timeout; v1 used `nix` the same way. |
| D12 | Captured stdout and stderr are capped at 16 MiB each; the excess is read and dropped. | A chatty child must not grow memory without limit or block on a full pipe. |
| D13 | The environment rule is enforced by clippy's `disallowed-methods`, allowed only in `main.rs`; the substring test is gone. | The substring test was trivially bypassed by an import; clippy resolves the path. |
| D14 | `main` routes `crook hook …` before clap, so every hook invocation exits 0. | Clap exits 2 on a usage error, which would break the hook contract (0020). |
| D15 | The release-only test step passes `--no-tests=pass`. | With no `#[ignore]` tests yet, nextest fails with "no tests to run". |
| D16 | No separate schema job: `tests/schema.rs` runs inside the normal test jobs once binary tasks 2.6 and 7.2 add it. | M1.6 asks for schema checks on both OSes, which the test jobs already give. |
| D17 | Archive, smoke, packslip and mod jobs stay out of `ci.yml` until release M2 to M4. | Their subjects do not exist yet. |
| D18 | Codecov uploads use OIDC, as v1 did; the repository has no secrets. | `gh secret list` is empty, and v1 never needed a token. |
| D19 | Coverage uploads fail the job on error and use the same pinned Codecov CLI (v11.3.2) as `codecov-notify`. | Review: a dropped coverage report left CI green while statuses were computed from partial data. |
| D20 | Codecov components list each module's root file (`src/files.rs` and so on) next to its folder; `main.rs` and `lib.rs` belong to `cli`; `src/testutil.rs` is ignored like tests. | Review: root files fell in no component, so coverage drops there could not fail a status. |
| D21 | The test jobs still install all of `mise.toml`. | Trimming saves minutes on a cold cache only; revisit if CI time hurts. |
| D22 | The mise shim is `${MISE_DATA_DIR:-${XDG_DATA_HOME:-$HOME/.local/share}/mise}/shims/crook`, in code, ADR 0019 and every plan. | Review: mise puts its shims under `MISE_DATA_DIR` or `XDG_DATA_HOME` when set (`XDG_DATA_HOME=/tmp/x mise doctor` showed `/tmp/x/mise/shims`); the fixed `~/.local/share` path would miss them. |
| D23 | Worktree removal keeps the worktree when it holds any ignored file, naming up to three. | Review: `git worktree remove` deletes ignored files such as `.env`; ADR 0023 says cleanup never loses work, which wins over tidiness. |
| D24 | `roster::load` reads `"version": 1.0` as 1. | JSON Schema treats 1.0 as the integer 1; loader and schema must agree. |
| D25 | Every path function returns a `Result`; a missing or relative `HOME` fails only when a path needs it, and relative or empty `XDG_*` values are ignored. | The XDG spec says relative values are invalid and must be ignored (review finding). |
| D26 | `flock::find` reports a folder with no roster, or a roster naming another flock, as a broken flock; `list` stays name-based. | Review nit: `find` ignored the roster; `status` must still be able to show broken flocks. |
| D27 | Slugs are at most 16 characters and must not look like an hc address (`t7`); child names at most 15. This replaces the 40-character limit in Q12 and Q45. | Captured from a scratch core: hc names are at most 32 characters of `a-z 0-9 - _ .` and must not be address-shaped, and the child's hc name is `<slug>.<child>` (Q3), so 16 + 1 + 15 fits. |
| D28 | Versions compare by semver precedence, pre-releases included (`0.1.0-rc.1 < 0.1.0-rc.2 < 0.1.0`). | The first release is `0.1.0-rc.1` (Q33); treating pre-releases as unknown would never move the `current` link between release candidates. |
| D29 | Preflight runs `hc --version`, then always `hc server start` with the scrubbed environment, then `hc schema`. | Every hc call except `--version` starts a core with the caller's environment if none runs (captured), and `server start` on a running core is harmless. |
| D30 | `plugin.json` carries `"author": {"name": "s0undt3ch"}`. | `claude plugin validate --strict` fails without an author, and the repository belongs to that account. |
| D31 | The coordinator skill writes the full shim expression in every Bash call rather than setting a shell variable once. | Shell state does not persist between Claude's Bash calls, so a variable set in one call is gone in the next. |
| D32 | The skills treat the exact wording of crook's messages as a guide, not a format to parse. | The binary plan does not fix that wording yet. |
| D33 | `crook close` kills the live children first, then marks the roster done, removes clean worktrees and prints its warnings, and kills the coordinator last. | Review: the coordinator runs `close` from inside its own terminal, so killing it first could kill `close` before the roster is marked and the warnings are seen. |
| D34 | The coordinator never uses AskUserQuestion while any child is live; every question to the maintainer is plain text. | Review: a blocked coordinator refuses child sends and may lose hc notes, for any question, not only the step-up one Q28 named. |
| D35 | Stop, close and step-up need consent typed in the coordinator's own pane; text arriving as `<hc from=…>` never counts as consent. | Review: a child, or text injected into a child, could otherwise impersonate the maintainer. |
| D36 | A slug starting with `t` and a digit is refused (`t7`, `t1x`). | hc refuses address-shaped names wider than `^t[0-9]+$` (it refused `t1x`); the coordinator's hc name is the bare slug. |
| D37 | Preflight's wait loop runs `server start` with the scrubbed environment before every `hc schema` retry. | Review: a bare `schema` could start a stopped core with the session's Claude variables still set. |
| D38 | The fake hc copies real hc 0.1.22 exactly (no labels from `run`, a bare-word status from `ls`, a finished parent accepted), checked against the captured fixtures. | Review: a fake kinder than real hc would let later milestones pass tests and fail for real. |
| D39 | A relative `CROOK_BIN` is refused, and the environment is carried as raw OS strings end to end. | Review: a relative path breaks in a child's own folder, and non-UTF-8 variables were being dropped from the core. |
| D40 | CI runs `claude plugin validate --strict plugin/` in the `plugin-check` job, installing the CLI with `npm ci` from the lock file in `.github/claude-code/` (Renovate's npm manager bumps it) on Node 24 (the CLI needs 22 or newer; jactionlint refuses an unlocked `npm install`). No JSON-shape fallback is needed. | The release plan left this unchecked. Checked: the npm package installs and `validate --strict` passes with an empty `HOME` and no login (2.1.332); the native binary comes from the package's postinstall, so `--ignore-scripts` breaks it. |
| D41 | `toolr ci plugin-check` is also a pre-commit hook (shape only, no tag compare); the CI job runs it with `--since-last-release` and fetches full history and tags. | The pre-commit job has no tags; the own job also hosts `validate`, so M2.6 is an own job. |
| D42 | The compatibility check covers agent files, skill folders and supporting files that a tagged `SKILL.md` names; other files may change. Tags sort by version with pre-releases below their release. | "Names that never change" freezes names a live conversation can still use; flagging every file would block harmless edits. |
| D43 | Agent bodies are capped at 30 lines and must name exactly one `crook-<role>` skill, with no `skills:` frontmatter key. | Plugin plan, agent files and Tier 1 structure test ("a line cap"); the real cap was not set, the files are 5 lines now. |
| D44 | The compatibility check compares with every release tag (`^v\d+\.\d+\.\d+(-pre)?$`) that is an ancestor of HEAD and not on it, not only the newest; it fails closed on a shallow clone, a git error or an unreadable tag list. | Review: a tag on HEAD compared a release with itself, and a live conversation can carry any earlier release's text. |
| D45 | Supporting files are protected when a tagged `SKILL.md`, or a supporting file it names, names them as a whole file name or path; substrings do not count. | Review: substring matching protected the wrong files, and a file named only by another supporting file was unprotected. |
| D46 | `plugin.json` may hold only metadata keys (`name`, `version`, `description`, `author`, `license`, `homepage`, `repository`, `keywords`, `$schema`); hook groups hold only `hooks` and hook entries only `type`, `command`, `timeout`. | Review: path keys would move components away from the folder layout, and a matcher would stop SessionStart firing on resume, clear and compact. An allow-list cannot go stale; a new metadata key needs a one-line edit. |
| D47 | The result template's `status` is checked by the binary's parser in `tests/plugin_templates.rs`; the Python check keeps only the headings. The Python frontmatter reader takes the first key, as the binary does. | One parser decides what crook reads; a second one could disagree. |
| D48 | Node is pinned to 24.22.3 in the plugin-check job, and `package.json` carries `allowScripts` for the Claude Code package, with `npm ci --strict-allow-scripts`. | npm 11.20 blocks unlisted install scripts, and the CLI's postinstall installs its native binary. Verified locally on npm 11.20.0; not verified on the npm 11.19.1 that Node 24.22.3 bundles, which runs scripts by default if it ignores the field. |
| D49 | The mod plan's M0 spike and every check in the maintainer's real herdr-app wait until the maintainer is present; the mod is built and tested with Node tests and `herdr-app check` only. | Earlier permission to test in the real app covered those specific tests; unattended runs do not extend it. |
| D50 | Each child has a `started` flag in the roster, as the coordinator does. It turns true once `hc run` succeeds, or when crook finds the terminal live (and, from milestone 8, when the SessionStart hook runs). `open` and `resume` launch with `--session-id` while it is false and `--resume` once it is true. | Review: a crash between the roster write and `hc run` left a child that every resume tried to `--resume` with a session Claude never created. |
| D51 | When `spawn` fails to launch a child, it deletes the empty branch it has just made, with `git branch -d`. ADR 0023 now names this one exception to "the branch is never deleted". | The retry with the same name (Q11) needs the branch gone, and `-d` refuses any branch with unmerged work. |
| D52 | A coordinator or child terminal counts as live only when hc shows an agent running in it. A bare shell with the same labels, as a core restore leaves, counts as gone: `crook open` replaces it, and the mod shows the flock as paused. | Review: herdr keeps labelled terminals across a core loss but restarts them as shells, so "a live terminal with the label" no longer means "the coordinator is there". |
| D53 | `close` and `stop` print each kept worktree as `warning: kept worktree <path>: <reason>`, and the mod counts only that prefix. | Review: other warnings, such as the `current` link ones, made a clean close look like it kept work. |
| D54 | `crook status --json` exits 0 even when hc is unreachable, and reports `hc_error` in the JSON. | The mod parses stdout only on exit 0. |
| D55 | The mod checks are two toolr commands in `tools/ci.py`: `mod-check` (static: `node --check` on each script, `mod.json` shape, the crook shim) runs in a CI job `mod-check` on Node 24.22.3; `mod-herdr-check` (`herdr-app check` on a temporary copy, with a throwaway `HERDR_APP_HOME`, plus the ids `crook-root` and `crook-new` in `--print-spec`) is the pre-commit hook, skipped with a message and exit 0 when `herdr-app` is not installed. CI also sets `SKIP: mod-herdr-check` on the prek step. | Release M3.1 to M3.5, mod M1.3 (Q34). Checked here: both pass on the real `mod/`, `mod/` stays clean after the hook, and broken copies fail. A hook that skips itself keeps a missing `herdr-app` from failing a contributor's commit. |
| D56 | `mod-check` reads each script from stdin with `--input-type=module`, and treats a missing `node` as a failure. The shim rule is: every bare `exec(` runs `"sh"` with `crookArgv(`, and `SHIM_SCRIPT` in `lib.js` holds the exact `SHIM` expression. | Without the module flag, a `.js` file is read as CommonJS or by syntax detection, depending on the nearest `package.json`. A rule on `exec("crook"` alone would let `exec(program, ...)` or `sh -c "crook ..."` through. Comments and `.exec(` on a regular expression are not calls. |
| D57 | The mod's own tests run in the `mod-check` job with Node's built-in coverage (`--test-coverage-include='mod/**'`, lcov), uploaded under flag `mod`. `.codecov.yml` gains a `mod` component and `after_n_builds` 4. The status schema test skips until `schema/status.schema.json` exists; the job needs no change when it does. The test-tools job also gets Node 24.22.3, because the new tests run `node --check`. | Release M3.4. No type check against a `herdr.d.ts` stub: the mod plan adds none, so the stub is not written (M3's note). |
| D58 | CodeQL's matrix gains `javascript-typescript`. | Release M3.6. `tests/` is already in `paths-ignore`, so the mod's tests are skipped. Not run on GitHub: the workflow's first run decides. |
| D59 | Mod tests run as `node --test 'tests/mod/*.test.mjs'`, not `node --test tests/mod`. | Node 24, pinned in CI, reads a bare folder argument as a single file and fails; the local Node 26 hid this. |
| D60 | Node is pinned in `mise.toml` at 26.13.1, the current LTS, and CI's three Node jobs get it from mise instead of `actions/setup-node`. | The maintainer asked for mise; 26 is the LTS line since 26.13.0 (2026-10-28), its npm 11.20.0 is the one `--strict-allow-scripts` was checked with, and the CLI installs and `claude plugin validate --strict` passes on it. A local Node 26 against CI's Node 24 had hidden a failing test command. |
| D61 | `mod-herdr-check` runs both `herdr-app` calls with `HOME` and the three `XDG_*_HOME` folders (as well as `HERDR_APP_HOME`) inside the temporary folder, and each call times out after 30 s. | Review: `herdr-app check` also writes per-folder state under the real home (`Library/Application Support/gpui-shell/apps/`), one folder per run. Checked after the change: no new folder appears there. |
| D62 | `mod-check` finds `exec` calls with a small JavaScript tokenizer, not a regular expression: comments are dropped, strings, template literals and regular expressions are single tokens, and `${}` bodies count as code. It reads the names bound to `exec` by `import … from "herdr"` (aliases, `* as h`, a default import), matches calls across whitespace, comments and `?.`, and requires `"sh"` then `crookArgv(`. A bare use of the name, or `h[...]`, fails. `SHIM_SCRIPT` must be assigned exactly the shim expression (string pieces joined by `+`), not contain it somewhere. | Review: the line-based check missed `exec\n(`, `exec/**/(`, `exec?.(` and aliases, a `//` inside a string hid a call, and a comment holding the old shim text passed the substring test. Not a full parser: dynamic `import()` and `const <built-in function exec> = h` are not followed. |
| D63 | `mod-check` reads `.js` and `.mjs` files under `mod/` recursively. `herdr-app`'s `--print-spec` must show each required id as an `:id[Str("…")]` attribute. The `mod` coverage component measures `lib.js` only, since `main.js` imports `herdr`; `ci.yml` says so. | Review nits. |
| D64 | `toolr ci stage-archive <triple> <version> [--binary] [--out] [--dist]` stages `crook-<version>-<triple>/` and, with `--dist`, writes the tar.gz and `.sha256` with Python's `tarfile` and `hashlib`. The build job uses it; no `tar`, `sha256sum` or `shasum` call remains. | Release M4.1, M4.2. One layout source for CI and the e2e harness; it also removes the GNU/BSD checksum split, and macOS `tar` cannot add `._` files. `--out` and `--dist` are plain strings because `ResolvedPath` requires the folder to exist. |
| D65 | `toolr ci archive-check <dir>` (a step of the `packslip-check` job, renamed "Archive and Packslip Checks") requires, per tarball, one top folder named as the tarball is, an executable `crook`, `plugin/.claude-plugin/plugin.json` and `mod/mod.json`, no member that is absolute or holds `..`, and a `.sha256` that matches when present. | Release M4.3. Not a separate job: it needs the same downloaded archives and one runner is enough. |
| D66 | The build job's inline staging and `release-patch-name` inputs are gone, and so is the rusqlite `CC_<triple>=musl-gcc` export. `musl-tools` and native runners stay as in v1. The job installs only `rust` through mise, and toolr through `setup-toolr`. | Release M4.2. The release patch inputs return with `apply-release-patch` in M7 (those actions are not on `main`). The binary has no C dependency now. Not run on GitHub: the first workflow run decides. |
| D67 | `packslip-check` and `targets` come from v1 unchanged apart from the skill-resource message ("ship inside plugin/"). The packslip CLI pin moves from 1.11.4 to 1.11.5, whose release attestation passes the same `gh attestation verify` call (checked locally). | Release M4.4. |
| D68 | `scripts/smoke-archive.sh <tarball> [expected-version]` is the smoke run: `env -i`, scratch `HOME`, four XDG folders and `HERDR_APP_HOME`; `_smoke-binary-archive.yml` checks out the repository and calls it. The "install is broken" check runs `crook status` with `plugin/` moved away. Until the binary has `completion`, `setup` and `doctor`, a run that prints `crook <cmd>: not implemented` is a `::warning::`, not a pass, and the checks after it are skipped (`pending` in the script). | Release M4.5. Those three commands are not in the binary yet; the checks for them are written and run as soon as the message goes away. Remove `pending` then. `status` was the command that fails without `plugin/` today; `doctor` may replace it. |
| D69 | The Stop hook sends `Result updated: <absolute path>`, never a bare path. ADR 0009 step 3, the binary plan and the coordinator skill now say so. | Review: a message starting with `/` can be read by Claude Code as a slash command or never delivered mid-turn, and hc only hides that while its `<hc>` tags are on. Spike 14 used this prefix. |
| D70 | SessionStart records the plugin version only on `startup` and `resume`; on `clear` and `compact` it creates a record only when none exists. | Review: an auto-compact after an upgrade would otherwise record the new version as loaded, and Stop would never send `/reload-plugins`. |
